# frontend-craft

> 模型生成的界面会收敛到同一张页面。这个 skill 强制你在写结构之前先做设计决策。

## 它解决什么问题

默认输出有极强的趋同性：居中 hero、紫蓝渐变、渐变文字、三个一模一样的卡片配 emoji 图标、每个容器都套 `border-radius: 12px` + 阴影。这套长相辨识度极高，而且它传达的信号是「没人真的做过设计决定」。

问题不在于这些做法本身违规，而在于它们是**默认值**，不是**选择**。

## 什么时候会触发

新建页面或组件、改造已有界面、或者你直接说「能用但看着很模板 / 很 AI」。

## 核心规则

### 先锁设计系统，再写结构

先定这几样，然后所有数值都从它们派生，不要在结构里散布魔法数字：

- **字号阶梯** 3-4 个层级，相邻层级要有可见的跳跃（比例约 1.25 以上）。满页 14-18px 等于没有层级。
- **间距阶梯** 一套基于 4 或 8 的级数。间距来自阶梯，不是 `margin: 13px`。
- **颜色** 一个强调色 + 一套中性色阶 + 语义色（成功/警告/危险）。
- **圆角与阴影** 最多两个圆角、1-2 档阴影。阴影表示「浮在上层」，不是装饰。
- **字体栈** 刻意选。一个有性格的标题字 + 一个易读的正文字，好过处处系统默认。

附带的 `assets/tokens.css` 是一个可以直接抄的起点。

### 反模式清单（默认删掉，除非有真实理由）

- 紫到蓝的渐变同时出现在 hero、按钮和标题上。
- 用渐变裁切文字做标题。
- 卡片上的玻璃拟态模糊，而卡片背后什么都没有。
- 三四个一模一样的 feature 卡片，每张配一个 emoji。
- 用 emoji 充当整个图标系统。
- 所有东西都居中，没有可扫描的对齐轴。
- 阴影 + 描边 + 大圆角同时套在每一个容器上。
- 演示页里留着「Lorem ipsum」「Feature One」「Item 1」这类占位文案。
- 用低透明度灰字做二级层级——为了层级把对比度做坏。

### 至少做一个有主见的动作

非对称分栏、真实网格并刻意安排跨列、一处全出血、超大字号的数字或标签、编辑式的字体搭配、一条强左对齐边。**有一个观点，并且贯穿它**，好过把所有安全选项堆在一起。

### 文案属于设计

在界面里写真标签、真空状态、真错误信息。「还没有发票——客户第一次结算后就会出现在这里」是设计工作，「暂无数据」不是。用户没给文案时，写合理的产品文案，并在交付报告里标明这是占位。

### 状态属于组件

默认状态不是完成态。要覆盖：**loading**（内容区域用形状匹配的骨架屏，短动作才用 spinner）、**empty**（说明会出现什么 + 给出创建它的那个动作）、**error**（说清失败原因、保留用户已输入的内容、提供重试）、**disabled/busy**、**溢出**（超长标题、无空格长串、RTL、0/1/1000 条）、**focus/hover**。

### 动效要挣得自己的位置

- 120-250ms，ease-out。
- 只动 `transform` 和 `opacity`；动 `width`/`height`/`top`/`margin` 会触发重排，而且通常更难看。
- 动效要传达信息：进入、离开、状态变化、确认。不做纯装饰。
- 必须尊重 `prefers-reduced-motion`，降级成无位移的状态切换。
- 不能让用户无法跳过的延迟动画，也不能让元素在指针下面移动。

### 响应式 = 先设计窄屏

先做窄的，再放宽。验证 320px，不只验证平板宽度。用 `clamp()` 做流体字号，`min()`/`max()` 做尺寸，组件在多宽度复用时用容器查询。**不要为了保住桌面布局而在小屏上藏掉核心功能**——要重构它。

## 怎么算做完了

**渲染出来看一眼再说完成**，并且要看空状态和错误状态，不只是「元素出现了」。如果没法渲染（没有浏览器环境），直接说「没渲染验证过」，不要描述成已完成。

## 怎么改成适合你的

- **token 值改成你们品牌的**，结构别动。
- 反模式清单可以加你自己的：如果团队里反复出现同一种廉价效果，把它写进去。**列具体样式（比如「低透明度灰字做二级文字」），比写「注意细节」有效。**
- 如果你们有设计系统，把「先锁系统」那一节替换成指向真实 token 文件或 Figma 变量的引用。
